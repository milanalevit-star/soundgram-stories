# SOUNDGRAM Stories v2

**Тестовое задание на позицию Frontend-разработчика в SOUNDGRAM.**

Telegram Mini App для создания музыкального портрета и публикации его в Telegram Stories. Вертикальная карточка объединяет музыкальную ауру, ведущие жанры и до трёх артистов. Приложение готовит PNG и открывает редактор Stories, а публикацию подтверждает сам пользователь.

**Тестовая ветка:** `soundgram-v2`. Обновления v2 предназначены для этой ветки; `main` сохраняется без изменений.

**Исходный код:** [soundgram-stories](https://github.com/milanalevit-star/soundgram-stories).

> **Статус:** тестовый прототип без подключения музыкального backend SOUNDGRAM. Имя, username и аватар берутся из Telegram; музыкальные данные — моки. Premium-виджет уже ведёт в настоящий SOUNDGRAM, но пока использует один жёстко заданный демонстрационный `share_code`, а не персональную ссылку текущего пользователя.

## 2. Запуск и тестовое окружение

Нужны Node.js поддерживаемой LTS-версии и npm.

```bash
git clone --branch soundgram-v2 https://github.com/milanalevit-star/soundgram-stories.git
cd soundgram-stories
npm install
npm run dev
```

Vite покажет локальный адрес. Проверка production-сборки:

```bash
npm run build
```

### Проверка в Telegram

Для v2 используется текущий тестовый бот, в обсуждении обозначенный как **«м2»**, и HTTPS **Preview URL** развёртывания ветки `soundgram-v2`, настроенный в BotFather. Точные username этого бота и актуальный Preview URL в доступных текстовых материалах не зафиксированы, поэтому здесь не подставлены предполагаемые ссылки.

Актуальный Preview URL нужно брать из развёртывания `soundgram-v2` в Vercel и использовать в настройках тестового бота. Старые ссылки из README v1 не подтверждают открытие v2. Бот `soundgram_app_bot` ниже — цель перехода в SOUNDGRAM, а не ссылка для запуска тестового прототипа.

Для локальной отладки внутри Telegram можно использовать HTTPS-туннель и временно настроить его в тестовом боте. Для проверки развёрнутого Preview локальный сервер и ngrok не требуются. Обычный браузер подходит для проверки вёрстки и PNG; Telegram-профиль в нём заменяется гостевым состоянием.

## 3. Данные и допущения

Моки в `src/mockData.ts` соответствуют предоставленным контрактам:

```ts
type GenreAuraItem = {
  genre_id: string;
  name: string;
  share: number;
  tracks_count: number;
};
type GenreAuraResponse = { items: GenreAuraItem[] };

type TopArtistItem = {
  artist_id: string;
  name: string;
  tracks_count: number;
  image_url: string | null;
};
type TopArtistsResponse = { items: TopArtistItem[] };
```

В данных сохранены три набора: `me`, `eva` и `alya`. **В пользовательском интерфейсе отображается только основной набор `me`**; переключатель между профилями убран. Дополнительные наборы оставлены в коде для разработки и проверки разных распределений жанров. Это не данные реальных медиатек пользователей Telegram.

Имя, username и фотография принадлежат тому пользователю Telegram, который открыл приложение, но **аура, число треков и топ артистов сейчас одинаковые для разных пользователей**: они берутся из основного демонстрационного набора. Часть распределений жанров основана на значениях, просмотренных в интерфейсе SOUNDGRAM. Поскольку исходные отображаемые проценты не всегда составляли 100%, доли нормализованы до суммы 1. Некоторые значения `tracks_count` демонстрационные.

**Свежие треки.** По условию задания недавно добавленные треки должны сильнее влиять на жанровое распределение. Но контракт содержит уже агрегированное поле `share` и не передаёт даты добавления отдельных треков. Поэтому фронтенд не вычисляет временные веса: предполагается, что backend рассчитает взвешенные доли и отдаст готовый ответ.

**Артисты.** В карточке отображаются до трёх первых артистов из переданного рейтинга (0–3). Для изображений используются внешние URL музыкального CDN, а не локальная папка с фотографиями.

## 4. Дизайн и концепция музыкальной ауры

### Основная идея

Цель дизайна — не просто показать музыкальную статистику пользователя, а превратить его музыкальные предпочтения в визуальный образ.

Мне хотелось, чтобы музыкальная аура стала своеобразным «отпечатком музыкального вкуса» человека.

В отличие от диаграмм и списков жанров, аура позволяет представить музыкальные предпочтения через сочетание цветов, их интенсивность и взаимодействие.

При этом визуализация не является случайным градиентом: её цветовая композиция формируется на основе музыкальных данных.

### Пример готовой музыкальной истории

![Музыкальная история SOUNDGRAM](docs/images/story-milana.png)

Пример карточки с Telegram-профилем, музыкальной аурой, тремя ведущими артистами и брендингом SOUNDGRAM.

### Один жанр — один цвет

В основе моей концепции лежит идея постоянного соответствия музыкальных жанров определённым цветам.

Это означает, что один и тот же жанр должен отображаться одинаковым цветом у всех пользователей SOUNDGRAM.

Например, если два человека слушают один и тот же жанр, в их аурах будет присутствовать общий цвет. Однако итоговые композиции могут различаться из-за других жанров и их относительных долей.

Таким образом, цвет становится не только декоративным элементом, но и способом визуально передать музыкальные предпочтения.

В тестовом приложении эта идея реализована через таблицу соответствия жанров и цветов. Для неизвестных жанров цвет стабильно вычисляется из идентификатора: один и тот же идентификатор получает одинаковый цвет при повторном отображении.

В перспективе такую систему можно было бы использовать и в основном приложении SOUNDGRAM, чтобы сделать музыкальные портреты более персонализированными и узнаваемыми.

### Почему ауры пользователей отличаются

Внешний вид музыкальной ауры зависит от нескольких факторов:

- Набора музыкальных жанров в медиатеке.
- Доли каждого жанра.
- Соотношения ведущих жанров.
- Цветов, закреплённых за этими жанрами.

Если у пользователя преобладает определённый жанр, его цвет будет заметнее в общей композиции.

Если музыкальные предпочтения разнообразнее, аура будет содержать больше цветовых сочетаний.

Благодаря этому пользователи с разными музыкальными вкусами получают разные визуальные образы.

При этом одинаковые исходные данные могут создавать одинаковые ауры. Индивидуальность достигается за счёт музыкальных предпочтений, а не случайной генерации цветов.

### Почему я выбрала именно такую форму

При разработке мне хотелось создать не просто визуализацию статистики, а образ, который ассоциировался бы с самой музыкой.

Поэтому вместо привычных диаграмм с чёткими границами я выбрала плавные, переплетающиеся цветовые потоки.

Такие формы напоминают движение, ритм и непрерывность звучания. Цвета не существуют отдельно друг от друга, а пересекаются и образуют единую композицию — так же, как разные жанры сочетаются в музыкальных предпочтениях человека.

Кроме того, мне хотелось, чтобы аура воспринималась не только как источник информации, но и как самостоятельный визуальный элемент, которым пользователю было бы интересно поделиться.

При этом интенсивность цветовых потоков зависит от долей соответствующих жанров.

Для сохранения читаемости в визуализации используются **до восьми ведущих жанров**. Это позволяет избежать чрезмерного смешения цветов, особенно если музыкальная медиатека пользователя очень разнообразна.

### Почему именно такой дизайн Stories

Карточка разрабатывалась специально для вертикального формата **9:16**.

Я учитывала, что Telegram Stories обычно просматривают быстро, поэтому зрителю должно быть достаточно нескольких секунд, чтобы понять, кому принадлежит музыкальный портрет и что именно он показывает.

Для этого информация распределена по визуальной иерархии:

1. **Верхняя часть — информация о пользователе.**

   Аватар, имя и username позволяют сразу понять, кому принадлежит музыкальная аура. В v2 под информацией пользователя добавлены названия трёх ведущих жанров, цветовые маркеры и проценты.

2. **Центральная часть — музыкальная аура.**

   Это главный визуальный акцент карточки. Она привлекает внимание цветом и формой.

3. **Топ-3 артиста — связь с реальной музыкой.**

   Фотографии и имена любимых исполнителей помогают зрителю быстрее понять музыкальные предпочтения человека. Они дополняют абстрактную цветовую визуализацию конкретной информацией.

4. **Нижняя часть — SOUNDGRAM.**

   Название проекта показывает, где был создан музыкальный портрет.

Мне было важно сохранить баланс между визуальной выразительностью и количеством информации. Поэтому карточка не перегружена дополнительными показателями и текстом.

Предполагается, что такая композиция будет понятна с первых секунд просмотра. При этом скорость восприятия пока не проверялась отдельным пользовательским исследованием.

### Связь с айдентикой SOUNDGRAM

При разработке я ориентировалась на существующую визуальную стилистику SOUNDGRAM: тёмный фон, яркие цветовые акценты, музыкальную тематику и внимание к личности пользователя.

Тёмный фон помогает выделить цветовые потоки ауры и фотографии артистов, не отвлекая внимание на второстепенные элементы.

При этом композиция не повторяет существующий экран музыкального портрета буквально, а адаптирует его идею под формат Telegram Stories.

Мне хотелось сохранить узнаваемость SOUNDGRAM, но сделать карточку самостоятельным изображением, которое органично смотрелось бы среди других историй Telegram.

### Возможное развитие концепции в SOUNDGRAM

В качестве возможного развития музыкального портрета SOUNDGRAM я предлагаю рассмотреть систему постоянных жанровых цветов. Она позволит связывать визуальный образ пользователя с его музыкальными предпочтениями и формировать разные цветовые композиции на основе жанрового распределения.

В таком случае музыкальная аура могла бы стать не просто декоративным элементом, а визуальным отражением индивидуальных музыкальных предпочтений.

Это открывает несколько интересных возможностей:

- **Визуальное сравнение музыкальных вкусов.** Пользователи могли бы замечать сходство своих аур и находить общие музыкальные предпочтения.
- **Узнаваемый цветовой язык жанров.** Определённые цвета постепенно могли бы ассоциироваться с конкретными музыкальными направлениями.
- **Персонализация профиля.** Аура могла бы стать одним из узнаваемых визуальных элементов пользователя.
- **Публикация в социальных сетях.** Индивидуальный музыкальный портрет мог бы мотивировать пользователей делиться своими предпочтениями.

В текущем прототипе концепция продемонстрирована на моковых музыкальных данных. Для полноценной интеграции потребуются реальные данные SOUNDGRAM и согласованная система соответствия жанров и цветов.

## 5. Генерация PNG и публикация

1. `StoryCard` отображает карточку средствами React, HTML и CSS.
2. Подготавливаются фотографии; сбой подготовки Telegram-аватара обрабатывается отдельно.
3. `html-to-image` создаёт базовый слой, Canvas объединяет его с аурой, аватаром, фотографиями или заглушками артистов и подписями.
4. PNG загружается в Cloudinary, который возвращает публичный HTTPS-URL.
5. Ссылка сохраняется для альтернативного сценария. Если возможности Telegram позволяют, вызывается `shareToStory()`; окончательную публикацию подтверждает пользователь.

При проверке доступности редактора учитываются наличие Telegram WebApp, версия API не ниже 7.8 и наличие `shareToStory`. Такая проверка не гарантирует открытие редактора на любой платформе и аккаунте. Сам вызов метода не подтверждает успешную публикацию.

Если редактор недоступен или не открылся, пользователь может нажать **«Открыть изображение истории»**, сохранить PNG и опубликовать его вручную. Это ссылка на подготовленное изображение; автоматическое скачивание внутри Telegram WebView не гарантируется. Если создание или загрузка PNG завершились ошибкой, публичная ссылка может не появиться.

Комбинированный экспорт сохраняет HTML/CSS для интерфейса и даёт контроль над графическими слоями через Canvas. Для `shareToStory` используется публичный URL, а не локальный `data:` или `blob:`.

## 6. Переход в SOUNDGRAM: Premium и без Premium

Для пользователя с Premium передаётся `widget_link` с подписью **«Мой SOUNDGRAM»**. В прототипе используется подтверждённый в обсуждении адрес:

```text
https://t.me/soundgram_app_bot?startapp=Jgu316un
```

`Jgu316un` — временно жёстко заданный демонстрационный `share_code`. Переход из опубликованной истории в настоящий профиль SOUNDGRAM проверен с другого аккаунта с Premium. Сейчас ссылка ведёт в один демонстрационный профиль независимо от того, кто создал карточку. Для интеграции backend должен передавать персональный `share_code` автора. Telegram ID нельзя считать идентификатором профиля SOUNDGRAM.

Без Premium виджет не передаётся; в подпись добавляется `@soundgram_app_bot`. **В выполненных проверках это упоминание не стало кликабельным.** Оно помогает найти приложение вручную, но не обеспечивает переход в профиль автора. Этот пункт ревью решён частично.

В проверенном Telegram Desktop виджет не появился независимо от Premium. Сохранение PNG также не переносит кликабельный виджет: он не является частью изображения.

## 7. Внешние изображения, CORS и безопасность Cloudinary

Telegram-аватар может отображаться в `<img>`, но не разрешать чтение пикселей через Canvas из-за CORS. В прототипе он подготавливается через Cloudinary. При отсутствии или недоступности фотографии используется заглушка. Ошибка подготовки аватара не должна прерывать весь сценарий публикации.

Фотографии артистов поступают с внешнего музыкального CDN. При экспорте учитывается их загрузка; недоступное изображение заменяется инициалом, а для пустого имени предусмотрен музыкальный символ. Внешний CDN должен разрешать использование изображения в Canvas.

**Демонстрационная схема загрузки не готова к production.** Используется unsigned upload в Cloudinary с параметрами в клиентском коде. Публичным upload preset могут злоупотреблять, а загруженные аватары и PNG доступны по публичным URL. Публичный адрес не обеспечивает приватность.

Перед production нужны серверная проверка Telegram `initData`, авторизованная загрузка с серверной подписью, ограничения формата и размера, rate limiting, политика хранения и удаления, а также учёт прав на изображения. Cloudinary API secret и токен бота нельзя помещать во frontend, переменные `VITE_*`, README или открытый репозиторий. `initDataUnsafe` используется для оформления, а не как подтверждение личности.

## 8. Совпадение превью и PNG

После ревью исправлены фон, плавные края ауры, порядок наложения артистов, фотографии и заглушки, белые подписи, жанры и оригинальный логотип. Визуальное соответствие PNG превью подтверждено в ходе проверки. Подписи артистов отрисовываются с контролем цвета, ширины и сокращения многоточием.

Это результат визуальной проверки, а не автоматическое доказательство попиксельного совпадения на всех устройствах. Возможны платформенные различия сглаживания и шрифтов.

## 9. Проверенные платформы

| Среда | Зафиксированный результат |
| --- | --- |
| iPhone / Telegram | Создание и публикация истории проверены; переход в настоящий SOUNDGRAM с другого аккаунта с Premium подтверждён. |
| Android / Telegram без Premium | Публикация истории проверена; виджета ссылки нет. |
| Telegram Desktop / macOS | Редактор открывается; в проверенном сценарии виджет ссылки не появился независимо от Premium. Доступен альтернативный путь через PNG. |
| Telegram Web / обычный браузер | Проверены подготовка и открытие PNG для сохранения. Прямая публикация через редактор не заявляется как подтверждённая. |

Результаты относятся к конкретным проверкам из обсуждения. Все версии Telegram, Android с Premium и слабые устройства отдельно не проверялись. Разворачивание Mini App зависит от возможностей платформы; единый полноэкранный режим для всех устройств не гарантируется.

## 10. Производительность и ожидание

После оптимизаций в обсуждении зафиксирован результат **2,73 с**. Это **однократный замер**, а не среднее, серия тестов или гарантированное время. Старые результаты v1 около 9 секунд не описывают текущую версию.

Нельзя приравнивать время подготовки в журнале приложения к времени фактического открытия редактора или успешной публикации. Для диагностики отдельно измеряются подготовка аватара, создание PNG и загрузка; сеть и работа Telegram добавляют собственные задержки.

Во время подготовки кнопка последовательно показывает:

1. «Подготавливаем фотографии…»
2. «Создаём историю…»
3. «Загружаем историю…»

Повторное нажатие заблокировано до завершения обработки. Результаты на слабом Android и статистика холодных и повторных запусков пока не собраны.

## 11. Реальные данные и краевые случаи

| Сценарий | Поведение v2 |
| --- | --- |
| Неизвестный жанр | Цвет стабильно вычисляется из `genre_id` вместо общего серого; уникальность цвета для каждого ID не гарантируется. |
| Ведущие жанры | До трёх жанров, отсортированных по убыванию доли. Для процентов учитывается сумма всех положительных конечных `share`; сумма трёх показанных процентов может быть меньше 100%. |
| Один или много жанров | Аура использует до восьми ведущих жанров; один жанр даёт один цветовой поток. |
| 0–3 артиста | Отображаются только переданные артисты, максимум три. При нуле блок артистов пуст, при одном нет вымышленных соседей; для двух предусмотрено отдельное расположение. Отсутствие артистов не отменяет ауру при наличии жанров. |
| Длинные имена | Ограничение ширины; подписи артистов сокращаются многоточием. |
| Нет `tracksCount` | Счётчик скрыт, фиксированное «178» удалено. Показывается только переданное конечное неотрицательное значение, включая 0. Количество не вычисляется суммированием жанров или артистов. |
| Нет Telegram-аватара или фото не загрузилось | Заглушка с первой буквой имени; ошибка подготовки аватара обрабатывается отдельно. |
| Фото артиста отсутствует или не загрузилось | Инициал или музыкальный символ вместо фотографии; экспорт учитывает загрузку изображения. |
| Нет фамилии или username | Необязательные поля не блокируют карточку. |
| Нет музыкальных данных | Пустое состояние и недоступная публикация. |
| Ошибка подготовки или загрузки | Понятное сообщение с предложением проверить соединение и повторить попытку; технические подробности остаются в консоли. Состояние ожидания сбрасывается. |

Кнопка может быть доступна до завершения загрузки всех фотографий: их ожидание и обработка ошибок выполняются в процессе подготовки PNG. Не заявляется отдельная блокировка кнопки на всё время первоначальной загрузки фото.

Поддержка краевых случаев не означает, что каждое их сочетание проверено на всех платформах. После последних исправлений в обсуждении подтверждена успешная production-сборка; это не новая проверка исходного кода в рамках подготовки README.

## 12. Что остаётся для интеграции

- Подключить backend SOUNDGRAM вместо моков, передавать реальные жанры, артистов и необязательный `tracksCount`.
- Получать персональный `share_code` автора вместо демонстрационного значения.
- Решить прямой переход в профиль без Premium; текущее некликабельное упоминание эту задачу не закрывает.
- Перенести загрузку Cloudinary в защищённую серверную схему и определить срок хранения изображений.
- Проверить дополнительные версии Telegram, слабые устройства, медленные сети и сочетания сетевых ошибок.
- Зафиксировать актуальные username тестового бота и Preview URL при передаче версии на проверку.
