SOUNDGRAM Stories
Telegram Mini App для создания и публикации музыкального портрета пользователя в Telegram Stories.
Тестовое задание на позицию Frontend-разработчика в проекте SOUNDGRAM.
1. О проекте
Приложение позволяет пользователю поделиться своим музыкальным вкусом через Telegram Stories.
При запуске Mini App получает имя, username и фотографию пользователя из Telegram. Музыкальные данные представлены в виде моков, соответствующих структурам API SOUNDGRAM.
На основе этих данных формируется вертикальная карточка с музыкальной аурой и любимыми артистами.
По нажатию кнопки «Поделиться в истории» приложение генерирует PNG, загружает его в облачное хранилище и открывает редактор Telegram Stories.
Технологии
- React + TypeScript + Vite
- Telegram Mini Apps API
- HTML Canvas API
- html-to-image
- Cloudinary
- CSS
Telegram-бот
@SoundGram_stories_test_bot
2. Запуск проекта
Требования
Необходимо установить Node.js и npm.
Локальный запуск
Клонировать репозиторий:
git clone https://github.com/milanalevit-star/soundgram-stories.git

Перейти в папку:
cd soundgram-stories

Установить зависимости:
npm install

Запустить сервер разработки:
npm run dev

По умолчанию приложение доступно по адресу:
http://localhost:5173

Проверить production-сборку:
npm run build

Запуск внутри Telegram
Для открытия Mini App в Telegram требуется публичный HTTPS-адрес.
Во время разработки использовался ngrok.
Пример запуска:
ngrok http 5173

Полученный HTTPS-адрес необходимо указать в настройках Mini App своего бота через BotFather.
Важно: если приложение использует локальный сервер и ngrok, оно доступно только пока работают оба процесса.
Бесплатный ngrok может показывать промежуточную страницу подтверждения перехода.
Приложение можно разместить на постоянном HTTPS-хостинге, чтобы избежать зависимости от локального компьютера.
3. Дизайн карточки
При разработке я ориентировалась на айдентику SOUNDGRAM и раздел музыкального портрета в существующем приложении.
Из SOUNDGRAM были взяты общая цветовая гамма, идея жанровой ауры и представление музыкальных предпочтений через артистов.
При этом карточка разрабатывалась специально для формата Stories, поэтому её композиция отличается от обычного экрана профиля.
Основные решения:
- Вертикальный формат 9:16.
- Имя, username и аватар пользователя размещены в верхней части.
- Музыкальная аура занимает центральную область.
- Три ведущих артиста расположены поверх ауры.
- В нижней части находится логотип SOUNDGRAM.
Цель дизайна — сделать музыкальный портрет узнаваемым и понятным за несколько секунд просмотра истории.
Почему отображаются только восемь жанров?
Данные могут содержать больше восьми жанров.
Например, один из тестовых профилей содержит 13 жанров.
Для визуализации выбираются восемь жанров с наибольшими долями. Это помогает сохранить выразительность цветовых потоков и избежать чрезмерного смешения цветов.
При этом остальные жанры сохраняются в данных.
4. Музыкальные данные
Для тестирования используются моковые данные в формате API SOUNDGRAM.
Жанровая аура
type GenreAuraItem = {
  genre_id: string;
  name: string;
  share: number;
  tracks_count: number;
};

type GenreAuraResponse = {
  items: GenreAuraItem[];
};

Поле share содержит долю жанра от 0 до 1.
Сумма долей всех жанров равна 1 с учётом погрешности вычислений JavaScript.
Топ артистов
type TopArtistItem = {
  artist_id: string;
  name: string;
  tracks_count: number;
  image_url: string | null;
};

type TopArtistsResponse = {
  items: TopArtistItem[];
};

В моках используются три музыкальных профиля.
Фотографии артистов загружаются по внешним URL музыкального CDN, а не из локальной папки проекта.
Учёт свежедобавленных треков
В SOUNDGRAM свежедобавленные треки должны сильнее влиять на жанровую ауру.
Frontend получает уже рассчитанное значение share. Даты добавления отдельных треков в предоставленном API-контракте отсутствуют.
Поэтому самостоятельный расчёт свежести треков в тестовом приложении не выполняется.
Предполагается, что в рабочей архитектуре backend рассчитывает взвешенные доли жанров, а frontend визуализирует результат.
Для демонстрации использованы значения, основанные на распределении жанров в интерфейсе SOUNDGRAM.
Поскольку отображаемые проценты не всегда суммируются до 100%, они нормализуются внутри моковых данных. Значения tracks_count, для которых не было исходной информации, являются демонстрационными.
5. Генерация PNG и публикация в Telegram Stories
Для создания изображения используется комбинированный подход.
Первый этап — HTML/CSS.
Компонент StoryCard отображает карточку в интерфейсе Mini App.
Библиотека html-to-image используется для получения фонового изображения и элементов интерфейса.
Второй этап — Canvas.
В итоговый Canvas отдельно добавляются:
- Музыкальная аура.
- Telegram-аватар.
- Фотографии артистов.
- Подписи артистов.
Такой подход позволяет контролировать порядок наложения элементов, форму обрезки изображений и прозрачность.
Третий этап — загрузка PNG.
Готовое изображение загружается в Cloudinary.
Cloudinary возвращает публичный HTTPS-адрес.
Четвёртый этап — Telegram Stories.
Приложение передаёт публичную ссылку в:
Telegram.WebApp.shareToStory(...)

Telegram открывает редактор Stories, в котором пользователь может проверить и опубликовать изображение.
Почему нельзя передать PNG напрямую?
Для shareToStory() используется URL изображения, доступный Telegram.
Поэтому недостаточно создать PNG только в памяти браузера: файл необходимо разместить по доступному HTTPS-адресу.
В прототипе эту задачу решает Cloudinary.
В рабочей архитектуре SOUNDGRAM такую загрузку можно реализовать через собственный backend и файловое хранилище.
Какие альтернативы рассматривались?
Экспорт всей DOM-карточки через html-to-image.
Этот вариант оказался недостаточно надёжным при работе с внешними изображениями и Canvas внутри Telegram WebView.
Полная ручная отрисовка Canvas.
Позволяет точно контролировать изображение, но требует отдельно реализовывать размещение текста и всех элементов интерфейса.
Комбинированный вариант.
Был выбран как компромисс между использованием HTML/CSS для интерфейса и контролем отдельных графических слоёв.
6. Внешние изображения и CORS
Одна из основных технических сложностей — перенос фотографий с внешних серверов в PNG.
Браузер может отображать изображение, но это не всегда означает, что его разрешено использовать для чтения пикселей через Canvas.
Telegram-аватар
Фотография пользователя получается из:
Telegram.WebApp.initDataUnsafe.user?.photo_url

При попытке непосредственно нарисовать Telegram-аватар на Canvas возникала ошибка:
The operation is insecure

Причиной стало ограничение безопасности Canvas при использовании изображения без необходимых CORS-разрешений.
Для тестового приложения реализован следующий способ:
1. Получить ссылку на аватар из Telegram.
2. Передать её Cloudinary для загрузки изображения сервером.
3. Получить URL фотографии в Cloudinary.
4. Загрузить изображение с поддержкой CORS.
5. Добавить его в итоговый Canvas.
Этот способ успешно проверен на тестовом Telegram-аккаунте.
Фотографии артистов
Изображения артистов загружаются с внешнего музыкального CDN.
При экспорте они добавляются в итоговый Canvas отдельно от фонового HTML-изображения.
Ограничения решения
В текущем прототипе используется публичная загрузка изображений в Cloudinary.
Это означает, что пользовательский аватар может оказаться доступным по публичному URL.
Для production-версии потребуется защищённая серверная обработка изображений, проверка авторизации, ограничение загрузок и управление сроком хранения файлов.
Текущий способ не следует считать готовой архитектурой безопасной обработки пользовательских фотографий.
7. Переход из истории в профиль SOUNDGRAM
При открытии редактора Stories приложение передаёт параметр widget_link.
Ссылка формируется в формате Telegram Mini App deep link:
https://t.me/SoundGram_stories_test_bot?startapp=profile_<telegram_user_id>

В тестовом приложении она открывает демонстрационный экран профиля.
В настоящем SOUNDGRAM вместо Telegram ID должен использоваться код профиля, полученный от backend.
Различия между платформами
Во время тестирования обнаружилось, что поведение ссылки различается.
На Telegram Desktop для macOS редактор Stories открывался, но автоматический виджет ссылки не отображался.
На iPhone ссылка появилась в редакторе Stories.
При этом наличие виджета и возможность его использования зависят от возможностей конкретной версии и платформы Telegram.
Ограничение: тестовое приложение не подключено к настоящему backend SOUNDGRAM, поэтому переход ведёт в демонстрационный профиль.
8. Шрифты
Часть текста карточки экспортируется из HTML/CSS через html-to-image.
Подписи артистов рисуются отдельно через Canvas.
Для ручной отрисовки используется Arial с заданными параметрами размера и начертания.
При экспорте шрифты могут отличаться от исходного отображения браузера, особенно при отсутствии нужного шрифта на устройстве.
Для длинных имён артистов реализовано сокращение текста с многоточием, чтобы надписи не перекрывали друг друга.
В дальнейшем можно использовать единый подключаемый шрифт и дожидаться его загрузки перед экспортом.
9. Поддержка платформ
Telegram Desktop — macOS
Проверено:
- Mini App открывается.
- Карточка отображается.
- Редактор Telegram Stories открывается.
- Автоматический виджет ссылки в проведённых тестах не отображался.
Telegram — iOS
Проверено на iPhone:
- Mini App открывается.
- Генерация карточки работает.
- Редактор Stories открывается.
- Виджет ссылки появился в редакторе.
При использовании бесплатного ngrok перед открытием приложения может появляться дополнительная страница подтверждения перехода.
Telegram — Android
Не тестировалось из-за отсутствия подтверждённых результатов проверки.
Telegram Web
Не тестировалось.
Недоступность Telegram Stories
Приложение проверяет версию Telegram API перед публикацией.
Если версия недостаточно новая, пользователь получает сообщение о необходимости обновления Telegram.
Для production-версии необходима дополнительная обработка платформ, на которых редактор Stories недоступен, например предложение скачать PNG.

11. Краевые случаи
В ходе разработки были проверены следующие ситуации:
Ситуация	Поведение
Нет Telegram-аватара	Цветной круг с первой буквой имени
Аватар не загрузился	Отображается первая буква имени
Артист без фотографии	Круг с первой буквой имени артиста
Один жанр	Аура формируется из одного цветового потока
Двадцать жанров	Выбираются восемь ведущих жанров
Длинное имя пользователя	Текст сокращается по ширине
Длинный username	Проверено отображение в карточке
Длинные имена артистов	Сокращаются с многоточием
Пустая медиатека	Показывается информационное сообщение, публикация недоступна
Неизвестный жанр	В алгоритме предусмотрен запасной цвет
Отсутствует фамилия	Карточка использует имя Telegram; фамилия необязательна
Отсутствует username	Блок username не отображается
Меньше трёх артистов	Отображаются доступные артисты, максимум три


Проверенные сценарии экспорта включали отображение букв вместо отсутствующих фотографий.
Неизвестный жанр, отсутствие username и неполный список артистов предусмотрены кодом, но отдельно не тестировались на всех платформах.
12. Известные ограничения
Проект является тестовым прототипом, поэтому:
- Музыкальные данные захардкожены.
- Нет подключения к настоящему backend SOUNDGRAM.
- Переход по ссылке открывает демонстрационный профиль.
- Изображения загружаются через Cloudinary.
- Внешние CDN могут быть временно недоступны.
- Загрузка пользовательского аватара требует отдельного решения по приватности для production.
- Поведение Telegram Stories зависит от платформы и версии Telegram.
- Android и Telegram Web не прошли практическое тестирование.
- При использовании ngrok доступность приложения зависит от запущенного локального сервера.
13. Возможные улучшения

1. Подключить реальные API GenreAuraResponse и TopArtistsResponse.
2. Использовать настоящий код профиля для deep link.
3. Перенести обработку пользовательских изображений в защищённый backend.
