# SOUNDGRAM Stories

**Тестовое задание на позицию Frontend-разработчика SOUNDGRAM.**

Telegram Mini App для создания музыкальной карточки пользователя и публикации её в Telegram Stories. Пользователь видит карточку со своей музыкальной аурой и топ-артистами, нажимает «Поделиться в истории», после чего открывается редактор Telegram Stories с подготовленным изображением.

**Ссылки:** [Telegram-бот](https://t.me/SoundGram_stories_test_bot) · [Работающее приложение (Vercel)](https://soundgram-stories.vercel.app) · [Исходный код](https://github.com/milanalevit-star/soundgram-stories)

> **Статус:** работающий тестовый прототип, не интегрированный с backend настоящего SOUNDGRAM. Музыкальные данные — моки; переход из опубликованной истории ведёт в тестовый Mini App и показывает экран-заглушку профиля автора с переданным идентификатором. Это **не** переход в реальный профиль SOUNDGRAM.

## 1. Реализованные возможности

- Получение имени, username и аватара из `Telegram.WebApp.initDataUnsafe.user` при запуске в Telegram.
- Просмотр музыкальной карточки в формате **9:16** с динамической жанровой аурой и тремя ведущими артистами.
- В основном интерфейсе отображается музыкальный портрет текущего пользователя Telegram на основе демонстрационного набора «me». Переключение на чужие профили не входит в целевой пользовательский сценарий.
- Дополнительные наборы «eva» и «alya» сохранены в `src/mockData.ts` только для разработки и проверки поведения ауры при разных жанровых распределениях; они не предназначены для выбора пользователем.
- Генерация PNG в браузере: HTML/CSS + `html-to-image` + ручная композиция слоёв через Canvas.
- Загрузка итогового PNG в Cloudinary и вызов `Telegram.WebApp.shareToStory()` с публичным HTTPS-URL.
- Передача ссылки на автора истории через `widget_link` и `startapp=profile_<id>`.
- Обработка пустого музыкального портрета, отсутствующих изображений, длинных имён и разного числа жанров.
- Индикация подготовки истории с блокировкой повторного нажатия.

**Технологии:** React, TypeScript, Vite, CSS, Canvas API, `html-to-image`, Telegram Mini Apps API, Cloudinary.

## 2. Запуск

Понадобятся Node.js и npm. Рекомендуется актуальная поддерживаемая LTS-версия Node.js.

```bash
git clone https://github.com/milanalevit-star/soundgram-stories.git
cd soundgram-stories
npm install
npm run dev
```

Vite выведет локальный адрес, обычно `http://localhost:5173/` (при занятом порте может выбрать другой).

Проверка сборки:

```bash
npm run build
```

### Запуск в Telegram

Telegram Mini App нужен **публичный HTTPS-адрес**. Текущая опубликованная версия размещена на Vercel: **https://soundgram-stories.vercel.app**. Этот адрес указан в настройках кнопки меню и основного Mini App тестового бота через BotFather. Доступ к приложению не зависит от запущенного локального сервера.

Для локальной разработки можно временно использовать туннель, например `ngrok http 5173`, и указать выданный HTTPS-адрес в BotFather. В этом случае должны работать и Vite, и туннель; для итоговой демонстрации **ngrok не требуется**.

В обычном браузере нет полноценного контекста Telegram (`initDataUnsafe.user`) и API публикации Stories: проверять конечный сценарий следует **из Telegram**. Локальная страница подходит для визуальной проверки и отладки генерации изображения.

## 3. Источник данных и допущения

Структуры моков повторяют контракт из задания:

```ts
type GenreAuraItem = {
  genre_id: string;
  name: string;
  share: number; // 0..1; сумма долей всех жанров = 1
  tracks_count: number;
};
type GenreAuraResponse = { items: GenreAuraItem[] };

type TopArtistItem = {
  artist_id: string;
  name: string;
  tracks_count: number;
  image_url: string | null;
};
type TopArtistsResponse = { items: TopArtistItem[] };
```

В `src/mockData.ts` заданы три тестовых музыкальных набора: основной `me` и дополнительные `eva`, `alya`. Дополнительные наборы нужны только для тестирования визуализации и крайних случаев; в финальном пользовательском интерфейсе переключатель между ними должен быть убран. **Имя, username и аватар берутся из Telegram, но музыкальные данные основного профиля пока моковые и не представляют настоящую медиатеку пользователя.** Проценты жанров взяты за основу из просмотренных данных интерфейса SOUNDGRAM; поскольку исходные отображаемые доли не всегда дают ровно 100 %, перед передачей в визуализацию они нормализуются до суммарной доли 1. Некоторые `tracks_count` заданы для демонстрации, а не получены от действующего API.

**Свежедобавленные треки.** По условию задания они должны влиять на жанровое распределение сильнее. Однако предоставленный контракт содержит уже агрегированные `share` и не содержит дат добавления отдельных треков. Поэтому прототип **не вычисляет временные веса самостоятельно**. Для интеграции предполагается, что backend подготовит взвешенные доли жанров, а frontend только отобразит результат.

**Топ-артисты.** Отображаются первые три позиции рейтинга, соответствующего числу треков в медиатеке; фотографии берутся из URL внешнего музыкального CDN, а не из локальных файлов проекта. Внешние адреса могут менять доступность и правила использования.

## 4. Дизайн и музыкальная аура

За основу взяты узнаваемые элементы SOUNDGRAM: тёмный фон, яркие цветовые акценты, музыкальная аура и акцент на артистах. При этом композиция адаптирована под носитель Stories, а не повторяет экран «Портрет» буквально: у вертикального изображения есть считанные секунды, чтобы передать характер музыкального вкуса.

Карточка размером **360 × 640 (9:16)** при экспорте рендерится в повышенном разрешении (масштабирование Canvas ×3). Верхняя зона отведена Telegram-профилю, центральная — ауре и артистам, нижняя — брендингу SOUNDGRAM.

Аура формируется средствами Canvas из цветовых потоков разных жанров. Доля жанра влияет на его визуальный вес. Для читаемости при большом числе жанров показываются **до восьми ведущих**, хотя полный набор жанров остаётся в моковых данных. Неизвестному жанру предусмотрен запасной цвет.

Компромисс: визуальный вес оставшихся восьми жанров пересчитывается внутри отображения, поэтому картинка передаёт **относительное соотношение ведущих жанров**, а не полный числовой график всех жанров.

## 5. Как карточка превращается в Telegram Story

1. React-компонент `StoryCard` отображает карточку в Mini App.
2. `html-to-image` получает базовый слой из DOM/HTML/CSS.
3. Canvas собирает итоговое изображение и отдельно наносит ауру, фотографии и подписи артистов, аватар Telegram (после подготовки внешнего изображения).
4. Полученный PNG загружается в Cloudinary; сервис возвращает доступный Telegram HTTPS-адрес.
5. Mini App вызывает `Telegram.WebApp.shareToStory(imageUrl, options)` — Telegram открывает редактор историй. **Публикацию подтверждает сам пользователь**, приложение не публикует историю автоматически.

`shareToStory()` работает с **URL изображения**, а не с локальным `blob:`/`data:`-адресом из браузера. Поэтому даже если PNG создаётся на клиенте, готовый файл должен быть доступен извне. В рабочем продукте загрузку стоило бы перенести в защищённое серверное хранилище.

**Почему такой способ:** чистый DOM-экспорт удобен, но при внешних изображениях и сложных Canvas-слоях возникают проблемы CORS и различия рендеринга. Полностью ручной Canvas обеспечивает контроль, но увеличивает объём кода для вёрстки. Комбинированный подход позволил оставить интерфейс на HTML/CSS и управлять сложными графическими слоями вручную.

## 6. Как зритель возвращается в профиль

При создании Story передаётся `widget_link` с deep link вида:

```text
https://t.me/SoundGram_stories_test_bot?startapp=profile_<telegram_user_id>
```

Тестовое приложение считывает `Telegram.WebApp.initDataUnsafe.start_param`, выделяет `profile_<id>` и открывает **демонстрационный экран** с идентификатором автора. Переход из **опубликованной** истории со второго аккаунта был проверен на iPhone: тестовый Mini App действительно открылся с переданным ID.

**Что пока не реализовано:** поиск профиля в реальной базе SOUNDGRAM, загрузка его музыкальных данных и переход непосредственно в рабочий `@soundgram_app_bot`. Демонстрационный экран не стоит воспринимать как настоящий музыкальный профиль. Для интеграции с продуктом понадобится ссылка, принятая в SOUNDGRAM (`t.me/soundgram_app_bot?startapp=<код профиля>`), где `<код профиля>` выдаёт backend. Подставлять Telegram ID вместо продуктового кода профиля без подтверждённого соответствия нельзя.

**Ограничения Telegram:** открытие редактора, появление интерактивного виджета и сама возможность публикации зависят от клиента Telegram, версии API и доступных пользователю функций (в том числе возможных ограничений аккаунта/подписки). Приложение не может гарантировать публикацию от имени пользователя.

## 7. Внешние изображения, CORS и конфиденциальность

**Telegram-аватар.** `Telegram.WebApp.initDataUnsafe.user?.photo_url` может отображаться на странице, но при попытке прочитать пиксели через Canvas внешний URL способен сделать Canvas небезопасным (`The operation is insecure`). В прототипе используется загрузка картинки по URL в Cloudinary и дальнейшая отрисовка с поддержкой CORS. При отсутствии фотографии отображается буква имени.

**Фотографии артистов.** Загружаются с внешнего CDN. Для экспорта также требуется корректный CORS; при отсутствующей или недоступной фотографии используется круг с буквой имени артиста.

**Важное ограничение безопасности:** прототип использует unsigned upload в Cloudinary; конфигурация такого пресета присутствует в клиентском коде. Это подходит для демонстрации, но не защищает хранилище от злоупотреблений. Публичные URL картинок могут сохранять пользовательский аватар. Для production нужны согласованная политика обработки аватаров, проверка `initData` на backend, аутентифицированная загрузка, ограничения формата/размера и частоты запросов, срок хранения и удаление файлов. Токены бота и API-secret не должны попадать во frontend или публичный GitHub.

## 8. Шрифты и точность изображения

В интерфейсе стили задаются через CSS; подписи артистов в итоговой PNG отрисовываются отдельно Canvas (Arial). Для длинных имён предусмотрено сокращение по доступной ширине с многоточием. При другом системном шрифте или версии WebView возможны незначительные расхождения с экранной карточкой.

Во время разработки обнаружилось расхождение между локальной и размещённой версиями: в старом опубликованном PNG подписи артистов оказывались чёрными, хотя в Mini App они белые. В локальном PNG исправленный вариант проверен; после обновления через GitHub/Vercel необходимо ориентироваться на повторную проверку уже опубликованной версии.

## 9. Проверка платформ и возможные ограничения

| Платформа | Что проверено | Результат |
| --- | --- | --- |
| **iOS (iPhone)** | Mini App → редактор → опубликованная история → переход со второго аккаунта | Проверено; виджет ссылки отображался, deep link открывал тестовый экран профиля |
| **Telegram Desktop (macOS)** | Mini App и редактор Stories | Открывались; в испытанном клиенте виджет ссылки автоматически не отображался |
| **Android** | Практическая проверка | Не проводилась |
| **Telegram Web** | Практическая проверка | Не проводилась |
| **Обычный браузер** | Отображение и локальный экспорт | Можно использовать для отладки; Telegram Story API вне клиента недоступен |

Код учитывает необходимость поддержки `shareToStory` соответствующей версией Telegram API. Там, где эта возможность отсутствует, полноценную публикацию через Telegram гарантировать нельзя. Нужен понятный fallback (например, скачивание PNG и инструкция по ручной публикации); его UX на всех платформах **не был подтверждён практическими испытаниями**. Фактическую доступность функции и ограничения Premium следует проверять на конкретном устройстве и аккаунте, а не считать единообразными.

## 10. Скорость и обратная связь

**Замеры от нажатия до редактора Stories** в проведённых тестах: **10,08 с; 8,25 с; 7,86 с** (среднее ≈ **8,73 с**). Холодный запуск после обновления иногда занимал до **15 с**.

Для двух отдельных измерений этапы выглядели так:

| Этап | Замер 1 | Замер 2 |
| --- | ---: | ---: |
| Подготовка аватара | 1,54 с | 2,04 с |
| Генерация PNG | 0,53 с | 0,48 с |
| Загрузка PNG | 3,12 с | 2,63 с |
| **Сумма измеренных этапов** | **5,19 с** | **5,15 с** |

Эти суммы **не равны полному времени до редактора**: часть задержек связана с другими операциями, ожиданием Telegram и сетевым окружением. Основная измеренная стоимость приходится на загрузку изображений. Во время обработки кнопка блокируется и показывает «Подготавливаем историю…». Замеров на слабом Android не было; производительность на нём остаётся неопределённой.

Возможные улучшения: кеширование подготовленного аватара, повторное использование готового PNG, сокращение числа сетевых запросов и снижение размера изображения при сохранении качества.

## 11. Краевые случаи

| Ситуация | Что сделано | Статус проверки |

| Ошибка загрузки изображения | Инициалы/резервное оформление | Проверялось для изображений; не все сетевые сбои проверены |
| Артист без фото | Инициал вместо фотографии | Проверено |
| Один жанр | Аура из одного основного цвета | Проверено |
| 20 жанров | Отображаются до восьми ведущих | Проверено |
| Длинное имя и username | Ограничение ширины/сокращение | Проверено визуально |
| Длинные имена артистов | Сокращение с многоточием также при Canvas-экспорте | Проверено |
| Пустой музыкальный портрет | Пустое состояние; кнопка публикации недоступна | Проверено |

## 12. Известные ограничения и дальнейшая интеграция

1. Медиатека и рейтинги артистов сейчас моковые; реальных запросов к SOUNDGRAM нет.
2. Ссылка из Stories открывает тестовое Mini App и заглушку автора по Telegram ID — **не реальный профиль SOUNDGRAM**.
3. При интеграции потребуется продуктовый `profile_code` от backend и переход в основной `@soundgram_app_bot`.
4. Доступность Telegram Stories, виджета ссылки и сценариев без Premium может различаться по платформам и аккаунтам.
5. Использование внешних музыкальных CDN требует проверки условий и устойчивости ссылок; производственная версия должна учитывать лицензии на изображения.
6. Нужна серверная обработка пользовательских изображений и контролируемое хранение PNG вместо открытой клиентской загрузки.
7. На Android, особенно слабом устройстве, и в Telegram Web практические тесты ещё не проводились.
8. Нужны полноценная обработка сетевых ошибок, повторные попытки и понятный fallback для публикации без `shareToStory`.
